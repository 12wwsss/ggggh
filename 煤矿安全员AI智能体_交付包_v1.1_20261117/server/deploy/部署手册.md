# 公网云部署手册（Ubuntu 22.04）

> 目标：把 `server` 部署到一台云服务器，小程序通过 `https://api.你的域名.com` 访问。
> 全程约 **2 小时**（不含 ICP 备案等待）。

---

## 0. 先买三样东西（甲方账号）

| 项 | 规格 | 参考价 | 备注 |
|---|---|---|---|
| 云服务器 | 2 核 4G / 40G SSD / Ubuntu 22.04 | ¥100–300/月 | 阿里云、腾讯云、华为云都行 |
| 域名 | 任意 .com/.cn | ¥50–80/年 | **主体必须是甲方** |
| ICP 备案 | — | 免费 | 7–20 天，**现在就去提交** |
| SSL 证书 | Let's Encrypt | 免费 | 脚本里用 certbot 自动申请 |

安全组/防火墙放行：**22（SSH）、80、443**。8789 不要对公网开放。

## 1. 连上服务器

```bash
ssh root@你的服务器IP
```

第一次登录改密码 / 配密钥（建议配密钥，别用密码）。

---

## 2. 上传代码

在你自己的电脑上执行（Windows PowerShell 同样适用）：

```bash
scp -r server root@你的服务器IP:/opt/coal-ai
```

或者服务器上装 git 后 `git clone`，看你习惯。

传完确认：

```bash
ls /opt/coal-ai
# 应该看到 index.js  kb  deploy  config.json ...
```

---

## 3. 一键部署

```bash
cd /opt/coal-ai
sudo bash deploy/install.sh
```

这个脚本会做：

1. 装 nginx、ca-certificates
2. 装 Node.js 20（已装则跳过）
3. 建运行账号 `coaliai`，把目录权限交给他
4. 注册 systemd 服务 `coal-ai`，开机自启、崩溃自动重启
5. 配 Nginx 反向代理（80 → 127.0.0.1:8789）
6. 放行 80/443（如果开了 ufw）
7. 自检 `/api/health`

看到 `部署完成` 就好。

---

## 4. 填密钥 + 域名

### 4.1 密钥

```bash
nano /opt/coal-ai/config.json
```

改三处：

```json
{
  "apiKey": "sk-甲方的key",
  "deployMode": "cloud",
  "baseUrl": "api.deepseek.com"
}
```

保存后重启：

```bash
systemctl restart coal-ai
systemctl status coal-ai --no-pager
```

### 4.2 域名

编辑 Nginx 配置，把 `api.example.com` 换成你的域名：

```bash
nano /etc/nginx/sites-available/coal-ai.conf
```

同时去域名服务商加一条 **A 记录**：`api` → 服务器公网 IP。

验证：

```bash
nginx -t && systemctl reload nginx
curl http://api.你的域名.com/api/health
```

### 4.3 HTTPS（必须，小程序只认 https）

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d api.你的域名.com
```

certbot 会自动改 Nginx 配置并配好 90 天自动续期。再验证：

```bash
curl https://api.你的域名.com/api/health
```

## 5. 小程序侧配置

### 5.1 改接口地址

`miniprogram/utils/config.js`：

```js
baseUrl: 'https://api.你的域名.com'
```

### 5.2 加请求白名单

微信公众平台（甲方账号）→ **开发管理 → 开发设置 → 服务器域名**：

- request 合法域名：`https://api.你的域名.com`
- uploadFile 合法域名：同上（以后上传图片要用）
- downloadFile 合法域名：同上

> 不配这一步，真机上所有请求都会被拦，报"不在合法域名列表"。

### 5.3 重新上传

开发者工具 → 上传 → 提交审核 → 发布。

## 6. 部署后自检清单

| 检查项 | 命令 / 方法 | 期望 |
|---|---|---|
| 服务在跑 | `systemctl is-active coal-ai` | `active` |
| 本地接口 | `curl 127.0.0.1:8789/api/health` | `"ok":true` |
| 公网接口 | `curl https://api.xxx.com/api/health` | `"ok":true` |
| 密钥生效 | 上面返回 `"key":"configured"` | — |
| 证书有效 | 浏览器打开域名，无警告 | 锁标志 |
| 小程序能问 | 手机问一句"瓦斯超限怎么办" | 有 AI 回答 |
| 日志在写 | `tail -f /opt/coal-ai/data/logs/chat.jsonl` | 有新行 |
| 重启能自恢复 | `reboot` 后等 1 分钟再访问 | 仍可用 |

## 7. 定时备份

```bash
sudo bash /opt/coal-ai/deploy/backup.sh
sudo crontab -e
# 加一行：
30 2 * * * /opt/coal-ai/deploy/backup.sh >> /var/log/coal-ai-backup.log 2>&1
```

备份内容：`data/`（问答日志、成绩）、`kb/`（知识库）、`config.json`。
建议再同步一份到对象存储或矿内 NAS。

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `502 Bad Gateway` | Node 没起来 | `journalctl -u coal-ai -n 50` |
| `curl` 超时 | 安全组没放 80/443 | 云控制台加规则 |
| 小程序报"不在合法域名列表" | 白名单没配 | 见 5.2 |
| 小程序报"连不上后端" | 用了 http 或域名解析错 | 必须 https，`nslookup api.xxx.com` 检查 |
| 回答很久不回 | 大模型慢 | Nginx 超时已设 90s，检查 `data/logs/error.jsonl` |
| 401 密钥无效 | key 填错 | 重新复制，必须以 `sk-` 开头 |
