# 安全与合规说明（对应方案"安全与合规"章节）

> 本文说明软件侧已经做到什么、哪些必须由甲方基础设施和测评机构完成。
> 用于投标应答、等保测评前自查、验收交底。

---

## 一、国产化适配

### 1.1 操作系统

| 项 | 情况 |
|---|---|
| 服务端 | Node.js 18+，**麒麟 V10 / 统信 UOS / 中科方德** 均可运行（Linux 通用） |
| 部署方式 | `deploy/install.sh` 支持 Debian 系；麒麟/统信同样适用 |
| 客户端 | 员工端为微信小程序，不依赖操作系统；管理后台为浏览器页面，国产浏览器（奇安信、360 企业版）可用 |

> 需甲方确认：服务器 CPU 架构（x86 / 鲲鹏 / 飞腾）。ARM 架构需使用对应的 Node.js 发行版（官方已提供 linux-arm64 包）。

### 1.2 数据库

当前版本使用**文件存储**（JSON），零外部依赖，适合单矿中小规模部署。

若甲方要求国产数据库，改造路径如下（**属二期工作量**）：

| 数据库 | 适配方式 | 工作量 |
|---|---|---|
| 达梦 DM8 | 换 `server/store.js` 为 `dmdb` 驱动实现 | 3–5 人日 |
| 人大金仓 KingbaseES | 同上，驱动 `kingbase` | 3–5 人日 |
| openGauss / TiDB | 兼容 PostgreSQL/MySQL 协议，改造更快 | 2–3 人日 |

已预留改造点：所有持久化读写都收敛在 `server/store.js` 的 `read/write` 两个方法，替换实现即可，业务代码不动。

建表参考（达梦 / 金仓通用 SQL）：

```sql
-- 问题工单
CREATE TABLE issue (
  id          VARCHAR(32) PRIMARY KEY,
  type        VARCHAR(32),
  title       VARCHAR(200),
  desc_text   VARCHAR(1000),
  urgent      SMALLINT DEFAULT 0,
  loc         VARCHAR(200),
  reporter    VARCHAR(64),
  team        VARCHAR(64),
  status      VARCHAR(16),
  created_at  TIMESTAMP,
  handled_at  TIMESTAMP,
  handle_note VARCHAR(600),
  handler     VARCHAR(64)
);

-- 答题记录
CREATE TABLE quiz_record (
  id        VARCHAR(32) PRIMARY KEY,
  user_name VARCHAR(64),
  team      VARCHAR(64),
  job       VARCHAR(32),
  notice_id VARCHAR(32),
  score     INT,
  total     INT,
  spent     INT,
  created_at TIMESTAMP
);

-- 题库
CREATE TABLE question (
  id      VARCHAR(32) PRIMARY KEY,
  job     VARCHAR(32),
  q_text  VARCHAR(500),
  options VARCHAR(2000),  -- JSON 字符串
  answer  SMALLINT,
  explain VARCHAR(1000),
  cite    VARCHAR(200),
  enabled SMALLINT DEFAULT 1,
  updated_at TIMESTAMP
);

-- 审计日志（等保要求留存 6 个月）
CREATE TABLE audit_log (
  id       BIGINT IDENTITY PRIMARY KEY,
  log_time TIMESTAMP,
  category VARCHAR(32),
  actor    VARCHAR(64),
  ip       VARCHAR(64),
  action   VARCHAR(64),
  detail   VARCHAR(2000)
);
CREATE INDEX idx_audit_time ON audit_log (log_time);
```

## 二、等保三级：软件侧已实现

| 控制项 | 实现情况 | 位置 |
|---|---|---|
| 身份鉴别（单因素） | 账号口令登录，8 位以上且含字母+数字 | `/api/login`、改密码接口 |
| 身份鉴别（双因素） | **已支持 TOTP 动态口令**（Google/Microsoft Authenticator），可开启/关闭 | `安全设置` 页、`/api/2fa/*` |
| 登录失败处理 | **连续 5 次失败锁定 10 分钟**，并记审计 | `LOGIN_FAILS` |
| 会话管理 | 服务端令牌 + HttpOnly Cookie，12 小时失效，改密后强制重登 | `SESSIONS` |
| 访问控制 | 后台页面与管理接口统一鉴权；**三员分立**按角色限制接口 | `ADMIN_PATHS`、`ROLE_RULES` |
| 安全审计 | 8 类日志：AI 问答、交卷、工单、题库变更、知识库变更、登录、宣贯、后台操作；后台可查询 | `/api/audit`、`data/logs/*.jsonl` |
| 数据完整性 | 知识库变更需**审批后生效**（先入待审区） | `/api/kb/approve` |
| 审计记录完整性 | **每条日志带哈希链**（prev + sha256），可一键校验是否被删改 | `/api/audit/verify` |
| 剩余信息保护 | 后台不展示明文密码；密钥仅在服务端配置文件 | — |
| 通信保密 | 支持 HTTPS 部署（Nginx + 证书），密钥不出服务端 | `deploy/nginx-coal-ai.conf` |
| 备份恢复 | `deploy/backup.sh` 每日备份知识库、数据、配置，保留 14 天 | `deploy/backup.sh` |
| 恶意请求防护 | 请求体大小限制、畸形请求返回 400 不影响服务、IP 限流 | 全局 |

## 三、知识库审批（内容可控）

流程：

```
管理员上传 → 进入「待审核」区（不参与检索）
   → 审核通过 → 移入知识库 → 立即生效并记审计
   → 驳回 → 删除并记审计
```

- 待审文件目录：`server/kb_pending/`
- 生效目录：`server/kb/`
- 审批动作写 `data/logs/kb.jsonl`，含操作时间，可在后台「审计日志」查询
- 小程序侧只检索已生效内容，**审核期间对外无感知**

> 若要"双人复核"（上传人 ≠ 审核人），需增加账号体系与角色，属二期。

## 四、记录留存与审计（监管留痕）

| 记录类型 | 内容 | 留存位置 |
|---|---|---|
| 提问记录 | 问题原文、命中知识块、耗时、token 用量 | `data/logs/chat.jsonl` |
| 学习/答题记录 | 姓名、区队、岗位、得分、题数、用时 | `data/logs/quiz.jsonl`、`data/quiz-records.json` |
| 工单记录 | 上报、处置、闭环全过程 | `data/issues.json`、`data/logs/issue.jsonl` |
| 知识库/题库变更 | 谁、何时、改了什么 | `data/logs/kb.jsonl`、`question.jsonl` |
| 登录与密码 | 成功/失败、IP、锁定 | `data/logs/auth.jsonl` |
| 后台操作 | 导出、审批等 | `data/logs/admin.jsonl` |

后台「审计日志」页可按类型筛选，最多展示 1000 条，支持导出。

**留存期限**：等保三级通常要求 ≥6 个月。当前按文件追加写入，未做自动清理；上线后建议：
- 每月归档一次到独立存储（`deploy/backup.sh` 已备份）
- 或按甲方要求接入日志平台

## 五、员工实名绑定（个人信息最小化）

首次打开小程序**由员工自助填写姓名 + 手机号**即可进入，不做短信/微信授权核验（内部培训场景，非强实名）。绑定后免登录。

| 项 | 做法 |
|---|---|
| 收集范围 | 仅姓名、区队、岗位；核验信息不落全号 |
| 身份证 | 不收集 |
| 手机号 | 只存 **SHA-256 哈希** + 后 4 位（用于展示 `****1234`） |
| 防冒用 | 一个身份只能绑定一台手机，换机需安全科在后台解绑 |
| 不上传 | 不获取位置、通讯录、相册、微信昵称头像 |

绑定成功后，答题成绩、问题上报自动归属到本人和所属区队，报表才有意义。

## 六、三员分立（已实现）

系统内置三个管理员账号，职责分离，**互不越权**（接口层强制校验，不只是菜单隐藏）：

| 账号 | 角色 | 能做什么 | 不能做什么 |
|---|---|---|---|
| `sysadmin` | 系统管理员 | 用户管理、知识库上传、题库、工单、报表导出 | **不能审批知识库**（必须安全管理员） |
| `secadmin` | 安全管理员 | 知识库审批、题库管理、工单处置、报表 | **不能管用户、不能看审计日志** |
| `auditor` | 审计管理员 | 只看审计日志、校验日志完整性、看统计 | **不能改任何内容**（题库/知识库/工单全拒） |

实测接口返回：

| 账号 | /api/users | /api/kb | /api/audit | /api/kb/approve | /api/questions |
|---|---|---|---|---|---|
| sysadmin | 200 | 200 | 200 | **403** | 200 |
| secadmin | **403** | 200 | **403** | 放行 | 200 |
| auditor | **403** | **403** | 200 | 403 | **403** |
| 未登录 | 401 | 401 | 401 | 401 | 401 |

- 初始密码与 `adminPassword` 一致（默认 `coal2026`），首次登录后各自修改
- 系统管理员可增删账号、重置密码、停用账号；**账号数不得少于 3 个**
- 后台菜单按角色自动隐藏，切换到无权限页面会被服务端拒绝

## 七、已实现的等保能力（可现场演示）

| 能力 | 演示路径 |
|---|---|
| 双因素登录 | 后台「安全设置」→ 生成密钥 → 手机验证器添加 → 启用 → 退出后重新登录需输入 6 位动态码 |
| 登录失败锁定 | 连续输错 5 次，提示「请 10 分钟后再试」 |
| 强口令策略 | 改密码时低于 8 位或不含字母+数字会被拒绝 |
| 知识库审批 | 知识库页上传 → 待审核区 → 通过后才生效 |
| 审计查询 | 「审计日志」页按类型筛选 8 类记录 |
| 日志防篡改 | 「审计日志」页点「校验日志完整性」，被删行/改行会指出具体行号 |
| 会话时效 | 12 小时自动失效；改密码立即踢下线 |

## 八、遗留与建议

1. **AI 调用会出公网**：问题文本与命中的规程片段会发送到 DeepSeek。若要严格"数据不出矿"，需更换为**矿内私有化模型**（vLLM/Ollama，配置项 `baseUrl` 已支持切换）。
2. **双因素为全局开关**：目前整个后台共用一个 TOTP 密钥，建议二期改为每个账号独立绑定。
3. **日志存储**：已有哈希链防篡改，但仍为本机文件，**需甲方提供集中日志平台并保留 6 个月**。
4. **数据库**：如甲方强制要求国产库，按本文 1.2 节改造，工作量已评估。
